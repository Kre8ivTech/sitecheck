# Report design contract

Surface: standalone audit report generated by a local command-line tool.

User job: understand coverage, identify the highest-priority problems, inspect evidence, and share a report.

Primary actions: filter findings, inspect evidence, export JSON, print/save PDF.

Hierarchy: target and coverage status → counts → prioritized findings → pages and links → journeys → screenshots → limits.

Direction: quiet editorial workspace, warm paper, forest ink, semantic severity colors, clear tables. Screenshots are audit evidence rather than decoration. This follows the product's evidence-first purpose; no external visual reference or private product data is used.

Viewports: 1440x900 and 390x844. On narrow screens navigation becomes horizontal, metrics form two columns, screenshots form one column, and data tables scroll inside their containers.

States:

- Loading: not applicable; static reports are presented after a command completes, with CLI progress during scanning.
- Empty: no findings or no matching filters; show an explanation and retain scope information.
- Error: failed pages/checks appear with specific details and next steps.
- Partial: distinct status and unavailable checks; never imply full coverage.
- Success: completed scoped scan, with or without findings and explicit limits.
- Permission: not applicable as an interactive report state; this local report has no login or permission-granting controls. Private-network refusal is a CLI error before scanning.

Checkable finish criteria: no page overflow at target widths, visible focus, labeled filters, keyboard-operable controls, no axe WCAG A/AA violations in the generated report, working filters/download, escaped audited content, and screenshots for both viewports.
